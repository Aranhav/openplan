# M3 Grid & Blueprint Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Builders and planners work inside models the way they do in Anaplan: Build navigation, the Lists, Time, Versions and Modules screens, a Blueprint with line item settings and a formula editor, and a virtualized, keyboard-first Grid with pivot, page selectors, filters, show/hide, conditional formatting, saved views, clipboard, undo and live updates.

**Architecture:** The engine gains a pure `view` module that turns a `ViewQuery` (pivot + selections + window) into a `ViewResult` (headers, cells, flags) on a model snapshot. The server exposes it as `POST /models/{id}/query` plus a members endpoint, stores saved views in Postgres, and pushes change events over a WebSocket authorised by a short-lived ticket (so the WebSocket can go straight to the API host when the web app sits behind Vercel). The web app adds a model-scoped Build sidebar and screens built from shadcn components; the Grid is a custom component (TanStack Virtual) whose logic (selection, keys, clipboard, undo) lives in pure, unit-tested TypeScript modules.

**Tech Stack:** Existing stack. New web deps: `@tanstack/react-virtual`, `@dnd-kit/core`, `@dnd-kit/sortable`, `@dnd-kit/utilities`, `@codemirror/state`, `@codemirror/view`, `@codemirror/language`, `@codemirror/autocomplete`, `@codemirror/lint`, `@codemirror/commands`, `@lezer/highlight`; shadcn components added with the shadcn CLI as needed (`context-menu`, `calendar`, `collapsible`, `radio-group`, `scroll-area`, `toggle-group`). Server: axum `ws` feature.

**Spec:** `docs/superpowers/specs/2026-10-15-openplan-design.md` §3, §7 (query, views, WebSocket), §9.1–9.6, §9.13, §12, §13.

## Global Constraints

- All M1 and M2 Global Constraints apply (problem+json, `ApiJson`/`ApiPath`, `Cache-Control: no-store`, snake_case JSON, UUID v7, no `query!` macros, no commented or unused code, commit trailers, engine has no I/O).
- UI is built only from shadcn/ui components in `web/src/components/ui` (add missing ones with `pnpm dlx shadcn@latest add <name>` from `web/`) and lucide icons. No other component kits.
- Every data screen has a loading skeleton, an empty state (icon, one sentence, primary action) and an error state (`ErrorState` with retry). Destructive actions use `AlertDialog`. Feedback uses Sonner. Forms use react-hook-form + zod with inline field errors, mapping server `errors[]` through the existing `web/src/lib/form-errors.ts`.
- Role gating (workspace role from M1 `useCurrentWorkspace`): `viewer` sees everything read-only (no create/edit/delete controls rendered; grid cells read-only); `planner` edits cell data only; `builder` and `admin` also edit structure. A model in `prod` mode keeps structure controls visible but disabled with tooltip "This model is in production mode. Structural changes arrive through ALM sync." The server enforces the same rules; the UI never relies on hiding alone.
- Controls for features of later milestones (export, comments, cell history, drill to source, presence avatars, Use mode, Data/Apps/Admin sidebar groups) are **not rendered** in M3. No dead buttons.
- Member keys (used in queries, views, page selections and edits): list leaf or ancestor item → its UUID string; list top level → `"top"`; time period → its label (`"Jan 26"`, `"Q1 FY26"`, `"H1 FY26"`, `"FY26"`, `"Total"`); version → its UUID string; line item → its UUID string. A member key converts to an M2 `CoordToken` by parsing it as a UUID (`Item`), otherwise as a string (`Period`).
- Engine spans are **byte** offsets; the web app converts them to UTF-16 string positions before using them in CodeMirror or `String.slice`.
- Light and dark mode are both verified (Playwright screenshots) for every new screen.
- Every new table enables row level security in the migration that creates it. Migration numbers: M1 0001–0002, M2 0003, M3 0004.

## Review Focus

1. Pre-switchover cells (version with a switchover, month before it) show the Actual value, carry flags `switchover` + `readonly`, and summaries over them equal what formulas see. Pinned in Tasks V1 and G3.
2. A paste or multi-cell edit with one invalid value is rejected as a whole (no partial write); read-only targets are skipped and counted; an optimistic edit that the server rejects reverts and a toast names the reason. Pinned in Tasks G1 and G3.
3. Live updates: a ticket is single-use, expires after 60 s, is bound to one user and model; a WebSocket from a foreign `Origin`, with a reused/expired ticket, or for a model the user cannot see is refused; a removed member's socket closes; a sequence gap triggers a full refetch. Pinned in Tasks V2 and L1.
4. Formula diagnostics on names with non-ASCII characters (`Umsätze`) underline exactly the offending text. Pinned in Task W5.
5. Collapsing hierarchy members and windowing keep `total_rows`/`total_columns` consistent; a window past the end returns an empty slice, not an error; hidden and collapsed members never leak cells. Pinned in Task V1.
6. A viewer's grid is read-only and the server rejects their writes (403) even when the request is crafted by hand. Pinned in Tasks V2 and G3.

### Task V1: Engine view queries (Sonnet)

**Files:** Create `crates/engine/src/view.rs`, `crates/engine/tests/view.rs`; modify `src/lib.rs` (pub use), `benches/recalc.rs`.

**Interfaces — Consumes:** M2 `Model::structure()`, `Model::read(li, cells)` (returns Actual for pre-switchover leaf cells, M2 ruling R15), `Model::line_item_errors(li)`, `Calendar` labels, `Structure::line_item_shape`. **Produces:**
- `#[derive(Clone, Debug, PartialEq, Eq, Hash, Serialize, Deserialize)] #[serde(tag="kind", rename_all="snake_case")] pub enum ViewDim { LineItems, List { list: ListId }, Subset { subset: SubsetId }, Time, Versions }`. A module's dims are its axes (each `AxisSpec` → `List`/`Subset`/`Time`/`Versions`) plus `LineItems`.
- `pub struct ViewQuery { pub module: ModuleId, #[serde(default)] pub line_items: Option<Vec<LineItemId>>, pub rows: Vec<ViewDim>, pub columns: Vec<ViewDim>, #[serde(default)] pub pages: Vec<PageSelection>, #[serde(default = "yes")] pub show_summaries: bool, #[serde(default)] pub collapsed: Vec<MemberRef>, #[serde(default)] pub hidden: Vec<MemberRef>, #[serde(default)] pub filters: Vec<RowFilter>, pub window: Window }`; `pub struct PageSelection { pub dim: ViewDim, pub key: Option<String> }` (None → default); `pub struct MemberRef { pub dim: ViewDim, pub key: String }`; `pub struct Window { pub row_offset: usize, pub row_limit: usize, pub col_offset: usize, pub col_limit: usize }`; `pub struct RowFilter { pub line_item: LineItemId, pub op: FilterOp, #[serde(default)] pub value: Option<Value> }`; `#[serde(rename_all="snake_case")] pub enum FilterOp { Eq, Ne, Lt, Le, Gt, Ge, Contains, IsBlank, NotBlank, IsTrue, IsFalse }`.
- `pub struct ViewResult { pub row_dims: Vec<ViewDim>, pub column_dims: Vec<ViewDim>, pub pages: Vec<PageMember>, pub rows: Vec<Header>, pub columns: Vec<Header>, pub total_rows: usize, pub total_columns: usize, pub cells: Vec<Vec<Cell>>, pub line_items: Vec<LineItemInfo> }`; `pub struct PageMember { pub dim: ViewDim, pub member: Member }`; `pub struct Header { pub members: Vec<Member> }` (one per dim, in dim order); `pub struct Member { pub key: String, pub label: String, pub depth: u8, pub is_summary: bool, pub has_children: bool, pub collapsed: bool }`; `pub struct Cell { pub value: Value, #[serde(skip_serializing_if="Option::is_none")] pub text: Option<String>, pub flags: Vec<CellFlag> }` (`text` = item name for item values, period label for period values); `#[serde(rename_all="snake_case")] pub enum CellFlag { Input, Calculated, Summary, Readonly, Na, Error, Switchover }`; `pub struct LineItemInfo { pub id: LineItemId, pub name: String, pub format: Format, pub is_input: bool, pub dims: Vec<ViewDim>, pub errors: Vec<FormulaError> }` (`dims` = the line item's own axes in axis order).
- `pub fn query(model: &Model, q: &ViewQuery) -> Result<ViewResult, EngineError>` and `pub fn members(model: &Model, module: ModuleId, dim: &ViewDim, show_summaries: bool) -> Result<Vec<Member>, EngineError>`.
- Rules:
  - Validation (`structure.invalid`): every module dim appears exactly once across rows, columns and pages; unknown dims, unknown member keys in pages/collapsed/hidden, `row_limit` > 1000 or `col_limit` > 200 are rejected with a message naming the problem. A window past the end yields empty `rows`/`cells`.
  - Members per dim. `LineItems`: `q.line_items` order if given, else ordinal order; no summaries. `List`: with summaries, tree order **parent first** — `top` (when the list has a top level), then each ancestor-list item followed by its descendants, down to the leaves; depth 0 for top; without summaries, leaves only in list order. `Subset`: its items in subset order, leaves only. `Time` (module level and optional time range): with summaries, **summary after its children** — months of a quarter, then the quarter; quarters of a half, then the half; halves, then the year; `Total` last; starting from the module's time level; without summaries, the module level only. `Versions`: version order, no summaries. `has_children` is true for summaries with children; `collapsed` reflects the query.
  - Collapsed summary members hide their descendants in that dim; hidden members are removed (a hidden parent leaves its children). Rows/columns are the cartesian product of the row/column dims' members (last dim fastest).
  - Default page member: list with top → `top`, else first leaf; subset → first item; Time → first period at the module level; Versions → the `is_current` version; LineItems → first line item.
  - Cell projection: the line item comes from the LineItems member (row, column or page). For each of the line item's own axes, the member of the matching view dim gives the coordinate (subset ↔ list by item identity). View dims the line item lacks are ignored (the cell broadcasts). The cell is `na` (blank value, `readonly`) when: the time member is finer than the line item's time level, the version is outside the line item's version scope, a subset/list member is not in the line item's axis, or a list dim of the line item doesn't exist in the module view. Otherwise it is a leaf (all members are leaves at the line item's level) or a summary (`summary` + `readonly`) read through `Model::read`.
  - Flags: leaf of an input line item → `input`; leaf of a formula line item → `calculated` + `readonly`; line item in error → `error` + `readonly` with blank value; leaf whose version has a switchover after the period's last month → `switchover` + `readonly` (value already substituted by `Model::read`).
  - Filters apply to row tuples ignoring the `LineItems` member. The filter line item's axes must be dims of this module (else `structure.invalid` "Filter line item 'X' has a dimension this view doesn't have."); its coordinate comes from the row member, else the page member, else (column dims) `top`/`Total`/current version. Number comparisons use `value`; `Contains` is case-insensitive on text/item names; `IsTrue/IsFalse` on booleans. A row passes when every filter passes.
  - Reads are batched per line item (one `Model::read` call per line item per query).

Refused with 403 problem+json **before** upgrading when: ticket unknown, expired, already used (tickets are removed on first use) or for another model; or `Origin` is present and differs from the `OPENPLAN_PUBLIC_URL` origin (when set). Re-checks membership (Viewer+). Server messages (JSON text frames): `{"type":"hello","seq":N}` on open; `{"type":"cells_changed","seq","line_item_ids","user_id"}`; `{"type":"structure_changed","seq"}`; `{"type":"resync","seq"}` when the broadcast receiver lags. Ping every 25 s. Every 60 s membership is re-checked; a removed member's socket closes with code 4403; a deleted model closes with 4404. Client messages are ignored in M3.
